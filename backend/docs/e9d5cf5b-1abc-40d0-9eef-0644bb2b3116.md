# API Files Updated for New Database Schema ✅

## Summary

All API files have been successfully updated to work with the new database schema. The changes ensure that the application uses the restructured tables with proper field mappings.

## Files Updated

### 1. ✅ `app/api/repositories.py` (Major Changes)

**Changes Made:**
- Added import for `UserCredentials` model
- Updated to use `Repository.full_name` instead of `Repository.name`
- Changed to get GitHub tokens from `user_credentials` table instead of `repo.encrypted_pat`
- Removed references to: `url`, `branch`, `owner_login`, `repo_name`, `stars_count`, `language`, `clone_size_mb`, `redis_cache_key`, `last_scan`
- Updated `create_repository()` to store PAT in `user_credentials` table
- Modified `clone_repository()` to build repo URL from `full_name` and use `default_branch`
- Updated `delete_repository()` and `delete_clone()` to fetch PAT from user credentials
- Removed `clone_size_mb` and `redis_cache_key` assignments

**Key Logic Changes:**
```python
# OLD: Get PAT from repository
if repo.encrypted_pat:
    pat = decrypt_pat(repo.encrypted_pat)

# NEW: Get PAT from user credentials
user_creds = db.query(UserCredentials).filter(
    UserCredentials.user_id == current_user.id
).first()
if user_creds:
    pat = decrypt_pat(user_creds.encrypted_token)
```

### 2. ✅ `app/api/pipeline_runs.py` (Major Changes)

**Changes Made:**
- Added import for `UserCredentials` model
- Changed all `run_id` parameters from `str` to `int` (now using database ID)
- Removed references to: `user_id`, `run_id`, `orchestrator_root`, `import_roots`, `output_dir`, `config_file`, `verbose`, `duration_seconds`, `error_traceback`
- Updated queries to join through `Repository` table for ownership checks (since `user_id` no longer exists on `PipelineRun`)
- Added usage of new fields: `input_mode`, `input_ref`, `task_id`
- Modified `create_pipeline_run()` to use simplified schema
- Updated `trigger_pipeline_run()` to:
  - Build repo URL from `full_name`
  - Use database ID instead of generating `run_id`
  - Fetch PAT from user credentials
- Changed duration calculation to compute on-the-fly from `started_at` and `completed_at`

**Key Logic Changes:**
```python
# OLD: Filter by user_id directly
query = db.query(PipelineRun).filter(PipelineRun.user_id == current_user.id)

# NEW: Join through repository for ownership
query = db.query(PipelineRun).join(Repository).filter(
    Repository.owner_id == current_user.id
)

# OLD: Calculate duration_seconds
run.duration_seconds = int((completed_at - run.started_at).total_seconds())

# NEW: Calculate on-the-fly when needed
duration = (run.completed_at - run.started_at).total_seconds()
```

## Breaking Changes

### API Response Changes

**Repository responses now exclude:**
- `name`, `url`, `branch`, `owner_login`, `repo_name`
- `stars_count`, `language`, `clone_size_mb`
- `redis_cache_key`, `encrypted_pat`, `last_scan`

**PipelineRun responses now:**
- Use integer `id` instead of string `run_id`
- Exclude `user_id`, `orchestrator_root`, `import_roots`, etc.
- Include new fields: `input_mode`, `input_ref`, `task_id`
- Duration must be calculated from timestamps

### Endpoint Changes

**Changed path parameters:**
- `/api/pipeline-runs/{run_id}` now expects integer ID, not string

**New authentication flow:**
- GitHub tokens now stored per-user in `user_credentials`
- Use `/api/credentials` endpoints to manage tokens
- All repository operations use the user's stored credential
