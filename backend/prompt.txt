## Phase 1: Tokenizer (tests first)
Create retrieval/tokenizer.py.

Spec:
- Input: a string. Output: a list of lowercase tokens in order of first occurrence. Keep duplicates here; counting happens later.
- Split on non-alphanumeric characters.
- For each identifier-like piece, also split camelCase, PascalCase, acronym boundaries and letter/digit boundaries:
  - count_vowels gives count, vowels, plus the full identifier count_vowels
  - VOWELS gives vowels
  - isPalindrome gives is, palindrome, plus ispalindrome
  - HTTPResponse gives http, response, plus httpresponse
  - parseHTTPResponse2 gives parse, http, response, 2, plus parsehttpresponse2
- The full identifier is emitted once per original identifier, lowercased, only when it contains a split.
- Drop tokens shorter than MIN_TOKEN_LEN = 2.
- Stopwords (config): def return self cls if else elif for in is not and or import from as none true false pass try except with while lambda the of to a an. The stopword list applies to split pieces AND full identifiers. So is is dropped from isPalindrome, and the full identifier ispalindrome is kept.
- Light stemming (config STEM_ENABLED = True), applied to split pieces only, never to full identifiers:
  - ies -> y
  - es removed only when the remaining stem is longer than 3 characters
  - s removed when the word is longer than 3 characters and does not end in ss
  - ed and ing removed when the remaining stem is at least 3 characters
  - Examples: validates -> validate, validate -> validate, lengths -> length, process -> process, class -> class.
- INCLUDE_COMMENTS = True (config). The tokenizer itself receives raw text; the chunk builder decides whether to feed it comment text.

## Phase 3: BM25 scoring and inverted index (tests first)
Create retrieval/bm25.py. Put the rule for query terms in the module docstring.

Formula (Okapi BM25, implemented here, no library):
- N = number of searchable chunks (non-test, non-empty).
- df(t) = number of searchable chunks containing t.
- IDF(t) = ln( (N - df + 0.5) / (df + 0.5) + 1 )
- score(chunk, query) = sum over DISTINCT query terms t present in the chunk of IDF(t) * tf * (k1 + 1) / (tf + k1 * (1 - b + b * len(chunk) / avgdl))
- Defaults from config: k1 = 1.5, b = 0.75. avgdl = mean token_count over searchable chunks.
- Query terms: each distinct term contributes once. Query repetition only changes the weight: weight = min(query_tf, QUERY_TERM_CAP) with QUERY_TERM_CAP = 2, and the contribution is multiplied by that weight. Document this in the docstring and test it.
- Inverted index: term -> postings list of (chunk_index, tf), sorted by chunk_index. search reads only the postings for query terms.

API:
- Bm25Index.build(chunks, params)
- Bm25Index.save(path)
- Bm25Index.load(path, index_json_path, repo_root): checks index_content_hash and per-file sha1 (Phase 2 freshness), raising StaleIndexError on mismatch.
- Bm25Index.search(query_terms: list[str], k: int) -> list[SearchHit]. SearchHit fields: symbol_id, rank, score, breakdown (list of dicts with keys term, df, idf, tf, weight, contribution, sorted by term).
- Results sorted by (-score, symbol_id). Zero-score hits never returned. At most k returned.
- An empty query raises ValueError with a clear message.

Persisted file bm25_index.json in the run folder, next to index.json: schema_version "bm25-1.0", index_content_hash copied from index.json, params, N, avgdl, chunks (sorted by id), postings (sorted by term).

Tests (tests/unit/test_bm25_scoring.py):
- Hand-computed score on a 3-chunk corpus. The expected numbers must be computed in the test by an explicit calculation written there. Do NOT call the implementation's helpers. Tolerance 1e-9.
- A rare term outranks a common term in the same position.
- Saturation: tf = 10 scores less than 10 times tf = 1.
- Length normalisation: a longer chunk with the same tf scores lower.
- Query cap: a term repeated 5 times in the query scores the same as 2 times.
- Ties: two identical chunks with different ids come back in id order.
- Empty query raises ValueError.
- Round trip: save then load gives identical search results (same ids, scores, breakdowns).
- A stored index_content_hash that differs raises StaleIndexError on load.
- Performance: synthetic 50,000 chunks with a Zipf-like vocabulary. Time a 6-term query with time.perf_counter over 20 runs; print the median; assert median < 0.1 s. Print build time too (no limit).
